Run your own Zephyr node

One machine, one Docker container. Your wallet talks to your own node, and the network gains a peer. No Cloudflare account needed.

What it needs

  • Disk: the database was about 25 GiB in November 2026 and grows with the chain. An SSD makes the first sync much faster.
  • Time: a sync from scratch took about 11.5 hours on one test machine in November 2026; expect anything from hours to days.
  • Network: outbound connections to other nodes (port 17766) and to the Zephyr price oracles (HTTPS). Opening 17766 inbound is optional and helps the network.
  • Docker on linux/amd64 or linux/arm64.

Choose an image

Both images run the Zephyr daemon the same way and are configured the same way. They differ in which binary they carry.

myzephyrzephyr
Binarya personal build of v2.3.0 with security fixesthe official v2.3.0 release, unchanged
Verified bya signed list of hashes, checked during the buildhashes recorded when the image was made; upstream publishes none
Security fixes30 fixes ported from Moneronone beyond v2.3.0
Finding peersworks out of the boxworks with the seed list the image sets; the seeds built into v2.3.0 no longer answer

A data directory works with either image; you can switch later.

Start it

With docker run:

docker run -d --name zephyrd --restart unless-stopped \
  -p 17766:17766 -p 17767:17767 \
  -v zephyrd-data:/data \
  ghcr.io/loki-notfound/myzephyr:latest

For the official release, use ghcr.io/loki-notfound/zephyr:latest instead. Or with Docker Compose, from a copy of deploy/standalone:

docker compose up -d
docker compose logs -f zephyrd

Watch it sync

curl -s http://127.0.0.1:17767/get_info | grep -E '"(height|target_height|synchronized)"'

When synchronized is true, point your wallet at 127.0.0.1:17767, or at the machine's address on your network.

Settings

The images take environment variables, for example:

PRUNE=truekeep roughly a third of the chain data
OUT_PEERS, IN_PEERSlimit the number of peer connections
ADD_PEERScomma-separated host:port list of nodes to connect to
RESTRICTED_RPCtrue by default: view-only RPC

The full list is in the repository.

RPC (port 17767) is published on every address of the machine, restricted to view-only calls and sending transactions. On a machine with a public address that makes it a public node, and Docker publishes ports past ufw. To keep RPC to the machine itself, publish 127.0.0.1:17767:17767 (RPC_BIND=127.0.0.1 with Compose). Never publish it with RESTRICTED_RPC=false. To serve others without an open port, put the node behind a Cloudflare Tunnel as described under high availability.

Other ways

  • myzephyr releases: the binaries of the myzephyr image, with a signed hash list.
  • ZephyrProtocol releases: the official binaries.
  • jnitecki/zephyr: a third-party image of v2.3.0; its source and binary origin are not published.
