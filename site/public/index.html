A public Zephyr node

node.lateo.dev is a free remote node for Zephyr wallets. Point your wallet at it and it syncs without downloading the blockchain yourself.

Use it

In a wallet, set the daemon or remote node to:

node.lateo.dev:443   (SSL)

With the command-line wallet, which detects SSL by itself:

zephyr-wallet-cli --daemon-address node.lateo.dev:443

The official Linux wallet of v2.3.0 does not find the system's certificate authorities on its own: it connects encrypted, but warns that it has not verified the node's certificate. Point it at the system's list to have the certificate checked, for example on Debian and Ubuntu:

SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt \
  zephyr-wallet-cli --daemon-address node.lateo.dev:443

Leave out --daemon-ssl enabled: with it, this wallet asks for a pinned certificate and does not start.

Or ask the node directly:

curl https://node.lateo.dev/get_info

What it is

  • Several machines, one address. The node runs on more than one host in different places. Each host runs its own copy of the Zephyr daemon next to a Cloudflare Tunnel connector; Cloudflare sends each request to a host that is up. When one goes down, the others keep answering.
  • Restricted RPC. Wallets can read the chain and submit transactions. Mining, peer and administrative calls are switched off.
  • No inbound ports. The hosts open nothing for RPC; all traffic arrives through the tunnel.
  • The daemon. Every host runs a myzephyr release, a build of Zephyr v2.3.0 with security fixes ported from Monero. It speaks the same protocol as the official release.
A remote node is a trust trade-off. It never sees your keys or your balance, but whoever runs it can see your IP address and when your wallet syncs or sends. For full privacy, run your own node.

A single node

One Docker container on one machine. No Cloudflare account, no domain. Your wallet talks to your own node.
