The node Run your own High availability

A highly available public node

This is how node.lateo.dev runs: one public hostname, several hosts, Cloudflare's free plan. When a host goes down, the others keep serving, and the tunnel needs no open port on any host.

wallet ── https ──▶ Cloudflare ─┬─ tunnel ──▶ cloudflared ─▶ zephyrd   host A
                                ├─ tunnel ──▶ cloudflared ─▶ zephyrd   host B
                                └─ tunnel ──▶ cloudflared ─▶ zephyrd   host C

What it needs

  • A domain on a Cloudflare account. The free plan is enough.
  • Two or more hosts, each meeting the requirements of a single node. One host works too: a public node without an open port, but not highly available.
  • Docker with Compose, and git, on every host.

1. Create the tunnel

In the Cloudflare dashboard, go to Zero Trust, Networks, Tunnels and create a tunnel of the Cloudflared type. The next screen shows an install command; you do not run it. The long string at its end, starting with eyJ, is the tunnel token: copy it.

The token is a secret: anyone who holds it can attach a connector to your hostname. Keep it out of repositories and screenshots.

2. Route a hostname

Add a public hostname to the tunnel, for example node.example.com, with service type HTTP and URL zephyrd:17767, exactly so: it is the daemon's name inside the setup, the same on every host.

3. Prepare each host

git clone https://github.com/loki-notfound/lateo-node
cd lateo-node/deploy/ha
cp example.env .env

Open .env in an editor and paste the token after TUNNEL_TOKEN=. The same file selects the official zephyr image instead of myzephyr (ZEPHYR_IMAGE); use the same image on every host.

4. Choose who reaches the RPC on the host

The tunnel needs no open port. Beside it, the setup offers the restricted RPC on port 17767 of the host, so the node is also usable directly. Decide before you start:

change nothingevery address of the host; reachable directly, without Cloudflare in front
RPC_BIND=127.0.0.1 in .envthe host itself only
delete the 17767 line under ports in compose.yamlno RPC on the host; the tunnel is the only way in
With nothing changed, a host with a public address answers anyone on port 17767. Those requests pass around Cloudflare and its rate limiting and show where the host is, and a firewall like ufw does not stop them: Docker publishes ports past it. For a public node whose hosts should stay unknown, delete the line. node.lateo.dev itself runs that way.

Port 17766 is published as well: other Zephyr nodes connect to it, not wallets. It is optional; delete its line too for a host with no open port at all.

5. Start

docker compose up -d --build
docker compose logs -f cloudflared

The connector joins the tunnel only while its daemon is healthy and synchronized. A new host first syncs the chain, which takes hours; until then it takes no requests. It has joined when the log says zephyrd healthy; starting the connector.

6. Check

curl -s https://node.example.com/get_info | grep -E '"(height|synchronized)"'

The tunnel's page in the dashboard lists one connector per host. To see the failover, run docker compose stop on one host and repeat the request: the others answer. docker compose start brings the host back.

7. Keep it up to date

One host at a time, so the others keep serving. Set ZEPHYR_IMAGE in .env to the new image tag, then:

docker compose pull zephyrd
docker compose up -d zephyrd

The host leaves the tunnel while its daemon restarts and returns by itself.

Good to know

  • The health check runs every 10 seconds and takes three failures to stop the connector, so a daemon that goes down can still receive requests for up to a minute.
  • Every request reaches the daemon from the connector's address, so the setup turns off the daemon's own ban on misbehaving clients. Add a rate limiting rule for the hostname in Cloudflare instead; node.lateo.dev allows 120 requests per 10 seconds per IP address.
