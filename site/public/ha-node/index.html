The node Run your own High availability

A highly available public node

This is how node.lateo.dev runs: one public hostname, several hosts, Cloudflare's free plan. When a host goes down, the others keep serving, and the tunnel needs no open port on any host.

wallet ── https ──▶ Cloudflare ─┬─ tunnel ──▶ cloudflared ─▶ zephyrd   host A
                               ├─ tunnel ──▶ cloudflared ─▶ zephyrd   host B
                               └─ tunnel ──▶ cloudflared ─▶ zephyrd   host C

What it needs

  • A domain on a Cloudflare account. The free plan is enough.
  • Two or more hosts, each meeting the requirements of a single node.
  • Docker with Compose on every host.

1. Create the tunnel

In the Cloudflare dashboard, under Zero Trust, create a Cloudflare Tunnel of the cloudflared type and copy the token from its install instructions.

The token is a secret: anyone who holds it can attach a connector to your hostname. Keep it out of repositories and screenshots.

2. Route a hostname

Add a public hostname to the tunnel, for example node.example.com, with service type HTTP and URL zephyrd:17767. Every host resolves that name to its own local daemon.

3. Start each host

On every host, from a copy of deploy/ha:

cp example.env .env           # put the token in TUNNEL_TOKEN
docker compose up -d --build

The connector attaches to the tunnel only while its daemon is healthy: the RPC answers, the node is synchronized and it is not behind its peers. A new host takes no requests during its first sync (hours), and a host whose daemon stops, restarts or falls behind drops out until it has recovered. Follow it with:

docker compose logs -f cloudflared

Copying the data volume of a synchronized host, with both daemons stopped, saves the first sync. Either image works; set ZEPHYR_IMAGE in .env to choose, and use the same image on every host. The connector is Cloudflare's own cloudflared, wrapped in a small script that Compose builds into an image on the host.

RPC on the host itself

The tunnel needs no published port. Beside it, the setup publishes the restricted RPC on port 17767 of every address of the host, so the node is also usable directly. Choose per host:

defaultevery address of the host; reachable directly, without Cloudflare in front
RPC_BIND=127.0.0.1 in .envthe host itself only
delete the 17767 line under ports in compose.yamlno RPC on the host; the tunnel is the only way in
With the default, a host with a public address answers anyone on port 17767. Those requests pass around Cloudflare and its rate limiting and show where the host is, and Docker publishes ports past ufw. For a public node whose hosts should stay unknown, delete the line. node.lateo.dev itself runs that way.

4. Check

curl -s https://node.example.com/get_info | grep -E '"(height|synchronized)"'

The tunnel's page in the dashboard lists one connector per host.

Good to know

  • Requests are spread over the hosts without stickiness, so two requests in a row can reach daemons that differ by a block for a moment.
  • The health check runs every 10 seconds and takes three failures to stop the connector, so a daemon that goes down can still receive requests for up to a minute.
  • Update one host at a time; its connector leaves the tunnel while the daemon restarts and returns by itself.
  • Every request reaches the daemon from the connector's address, so the setup turns off the daemon's ban on RPC errors. Use Cloudflare's rate limiting on the hostname instead.
  • The daemon matches RPC paths including the query string: /json_rpc?x=1 is a 404. Do not rewrite query strings in front of it.
  • A website on the same hostname, like this one, must claim exact paths only. A catch-all route would swallow /json_rpc and break wallets.
